WHO IS HUMAN · BUILD & DEPLOY

특수인공지능대응센터
게임 빌드 · 실행 · 배포

저장소 하나가 프론트(Vite + React)와 서버(Cloudflare Worker + Durable Objects)를 함께 담는다. 로컬에서 5분 안에 돌리고, 명령 두 줄로 배포한다.

v1.1 · 2026-09-05 · 개발자 · 운영자용 요약본

1. 구성과 요구 사항

브라우저 (Vite · React 19 · three.js)⇄ WebSocket ⇄ Cloudflare Worker (방마다 Durable Object)→ LLM · TTS · Supabase
Node.js · npmNode 20 이상 권장 (저장소에 버전 고정 없음). npm install이 git 훅(비밀 키 커밋 차단)도 함께 건다.
Cloudflare배포 계정 + wrangler(devDependency에 포함). 로컬 실행에는 계정이 필요 없다.
LLM 키봇 대사·관리 AI의 말 읽기에 쓴다. 없어도 판은 돈다 — 봇은 조용해지고 의심도는 규칙 표식으로만 움직인다.
선택ElevenLabs(목소리, 없으면 브라우저 음성), Supabase(구글 로그인, 없으면 게스트 닉네임).

2. 로컬 실행

npm install
cp .dev.vars.example .dev.vars      # 키 이름만 들어 있다 — 값은 각자 채운다
npm run worker:dev                  # 서버  http://localhost:8787
npm run dev                         # 프론트 http://localhost:5173  (터미널 하나 더)

프론트는 /world-ws를 워커로 프록시한다. 포트를 바꾸려면 두 터미널에 같은 WORKER_PORT를 준다.

환경 변수 (.dev.vars · 배포는 wrangler secret)

이름켜는 것없으면
OPENAI_API_KEYLLM — 봇 대사 · 관리 AI 읽기 · AI 전략 (배포본의 경로)봇 침묵, 규칙 폴백
ANTHROPIC_API_KEYLLM — 있으면 OpenAI보다 우선 (개발 비교용)선택
ELEVENLABS_API_KEY (+ 목소리 id)관리 AI 방송 · 프롤로그 목소리브라우저 Web Speech로 대체
SUPABASE_URL · SUPABASE_ANON_KEY · WORLD_TICKET_SECRET구글 로그인과 이름 보호로그인 꺼짐, 게스트로 입장
로컬에서 키 없이 봇 대사를 보려면 워커가 개발 서버의 Claude Code 구독 경로를 자동으로 두드린다(mode: dev). 배포본은 OPENAI_API_KEY 하나만 넣는다.

3. 플레이 확인

  1. http://localhost:5173/intro → 입장하기 → (로그인) → 방 목록 → 대기방 → 시작.
  2. 빠른 확인: http://localhost:5173/interrogation?code=123456 처럼 숫자 방 번호로 바로 들어가면 나 + 대역 2 + AI 1의 4인 판이 자동으로 열린다. 프롤로그 → 대화 → 낙하 생존 순으로 돌면 정상이다.
  3. 같은 번호에 지난 판이 남아 있으면 프롤로그 없이 중간부터 보인다. 새 번호를 쓴다.

4. 테스트 · 빌드 · 배포

npm run typecheck     # 프론트 + 워커 타입 검사
npm test              # vitest — 규칙 · 엔진 · 화면 테스트 2,000여 개
npm run build         # typecheck + vite build → dist/
npx wrangler deploy   # dist/ 와 워커를 한 번에 배포 (사람이 직접 실행)
배포 단위워커 하나. 정적 프론트(dist/)를 워커의 assets로 함께 올린다. WebSocket과 API가 같은 오리진이라 추가 설정이 없다.
배포 후 확인/health → ok, 인트로 → 방 입장 → 프롤로그가 흐르면 끝.
바꾸지 말 것wrangler.jsonc의 Durable Object 바인딩과 migrations 태그 — 방 저장소의 이력이라 되돌릴 수 없다.
알려진 불안정 테스트무작위 기반 테스트 두어 개(quick · say)가 가끔 실패한다. 다시 돌리면 통과한다.

5. 문제 해결

증상원인 · 조치
「연결 실패 — 워커가 떠 있어야 한다」워커가 안 떠 있다. npm run worker:dev. 포트를 바꿨으면 양쪽에 같은 WORKER_PORT.
방 번호를 넣었는데 접속이 안 된다방 번호는 숫자 1~6자리만 받는다.
프롤로그가 안 나오고 곧장 대화·시험이다같은 번호에 지난 판이 남아 있다. 새 번호로 들어간다(끝난 판은 30초, 버려진 판은 90초 뒤 사라진다).
봇이 조용하다① 발언권이 0 — 봇도 같은 규칙. ② LLM 키가 없고 개발 서버도 못 찾았다.
프롤로그 자막은 흐르는데 소리가 없다ELEVENLABS_API_KEY가 없다. 방송은 Web Speech로 대체된다.
