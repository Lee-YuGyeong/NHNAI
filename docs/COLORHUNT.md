# 🎨 색 사냥 — GAME 3 상세 기획

> **보이는 색은 물체의 성질이 아니다 — 조명의 스펙트럼 × 표면의 반사율의 곱이다.**
> 조명에서 파장 하나를 빼면 어떤 색은 죽고, 어떤 색들은 서로 합쳐진다.
> 이 법칙 하나가 게임의 전부다 — 화면에 필터를 씌우는 연출이 아니라, 규칙 그 자체다.

- 한 줄: **지시된 색의 구슬만 주워라. E 로 줍는다. 빛은 도중에 바뀐다.** (`engines.ts` 지시문 그대로)
- 소재 키워드 매핑: 「물리법칙 — 속도 · 빛과 색 · 중력」 중 **빛과 색** 축을 맡는다
  (중력 = 낙하 생존, 속도 = 정지선 — 이 종목이 없으면 키워드 세 갈래 중 하나가 빈다)
- 판정: 이벤트 기반, 물리 시뮬레이션 없음 (PLANNING §2.3)
- 시행: **60초 1회, 20초마다 조명 전환** — 라운드 없음, 낙하 생존 · 정지선과 같은 틀
- 설계 목표: **못 푸는 문제가 아니라 느리게 푸는 문제.** 사람은 결국 풀 수 있어야 하고(§5),
  판별은 정답률이 아니라 **전환 직후의 멈칫**(P3)에서 난다(§8)

---

## 1. 쓰는 법칙

```
표시색 (R,G,B) = 조명 (R,G,B) × 반사율 (R,G,B)   — 성분별 곱
```

물리적으로는 연속 스펙트럼 × 분광 반사율의 적분이지만, RGB 3채널 근사로 충분하다 —
셰이더 없이 서버의 곱셈 한 줄과 조명 값 교체로 구현된다(PLANNING §2.3 "셰이더 1장"보다도 싸다).

조명에서 적색 파장을 빼면(조명 = `0,1,1`):

- 빨간 구슬 → 반사할 파장이 없다 → **검게 죽는다**
- 노란 구슬(적+녹 반사) → 녹색 성분만 남아 **초록으로 보인다** — 진짜 초록과 **합류**한다
- 파란 구슬 → 그대로 파랗다 — **불변**

"초록으로 보이는 것" 안에 진짜 초록과 원래 노랑이 섞이는 순간, 지시가 퍼즐이 된다.

## 2. 팔레트 — 7색 반사율 표 (서버 전용)

| 구슬 | 반사율 R, G, B | 비고 |
|---|---|---|
| 빨강 | 0.88, 0.06, 0.06 | |
| 노랑 | 1.00, 0.85, 0.06 | |
| 초록 | 0.06, 1.00, 0.06 | |
| 청록 | 0.06, 0.85, 1.00 | |
| 파랑 | 0.05, 0.05, 0.88 | |
| 흰색 | 1.00, 1.00, 1.00 | |
| 검정 | 0.05, 0.05, 0.05 | **미끼 전용** — 목표색으로 절대 나오지 않는다 |

이 표는 `worker/src/trial/` 안(= `condition.ts` 옆)에만 산다 — 클라이언트에는 곱셈이 끝난
**표시색만** 내려간다(P8, §7).

### 차단별 표시색 — 게임이 이 표에서 나온다

**적색 차단** (조명 `0, 1, 1`):

| 구슬 | 표시색 | 무슨 일이 벌어지나 |
|---|---|---|
| 빨강 | ≈ 검정 | **죽는다** — 검정 미끼와 합류 |
| 노랑 | 어두운 초록 | ┐ **합류쌍** — 밝기 15% 차이만 남는다 |
| 초록 | 밝은 초록 | ┘ |
| 청록 | 어두운 청록 | ┐ **합류쌍** |
| 흰색 | 밝은 청록 | ┘ |
| 파랑 | 파랑 | **불변** — 자유색 |

**녹색 차단** (조명 `1, 0, 1`):

| 구슬 | 표시색 | 무슨 일이 벌어지나 |
|---|---|---|
| 초록 | ≈ 검정 | **죽는다** — 검정 미끼와 합류 |
| 빨강 | 어두운 빨강 | ┐ **합류쌍** |
| 노랑 | 밝은 빨강 | ┘ |
| 파랑 | 어두운 파랑 | ┐ **합류쌍** |
| 청록 | 밝은 파랑 | ┘ |
| 흰색 | 마젠타 | **유일색** — 자유색 |

구조가 대칭이다: 매 차단마다 **죽는 색 1 + 합류쌍 2 + 자유색 1**. 청색 차단은 쓰지 않는다 —
60초에 구간이 셋뿐이고 첫 구간은 기준광이어야 해서다(PLANNING §2 "첫 실행은 기준 조건",
`COLORHUNT_BLOCK = [null, red, green]` 그대로).

**밝기 갭 12~15%는 규칙이다: 합류쌍의 표시색을 완전히 같게 만들지 않는다.** 사람이 푸는
길(§5-②)을 항상 남기고, 픽셀값 비교 치팅이 눈보다 크게 유리하지 않게 한다. 이 갭이 주
난이도 노브다(§11).

## 3. 타임라인

```
t=0      시작 — 기준광(백색) · 목표색 ① 공지
t=0~20   구간 1 · 기준 기록 — 모든 색이 구별된다.
         개인별 평상시 페이스 · 정답률이 여기서 잡힌다 (P2 편차의 분모)
t=20     적색 차단 (0.5초 램프) · 목표색 ② 공지     ← P3 태깅 창 [20, 23]
t=20~40  구간 2
t=40     녹색 차단 · 적색 복구 (0.5초 램프) · 목표색 ③ 공지  ← P3 태깅 창 [40, 43]
t=40~60  구간 3
t=60     종료 → 결과 모달 (PLANNING §3, 5~8초 고정)
```

관리 AI가 정할 수 있는 것은 red/green의 순서와 목표색 난이도(§4)뿐 — 구간 1 기준광은 불변.

## 4. 목표색 — 난이도가 여기 산다

구간마다 목표색 1개. HUD에 **원색 스와치 + 이름**으로 뜬다(스와치는 조명 밖 UI라 원색 —
맵 안 견본판(§6)은 조명 적용색. 이 대비가 "조명이 색을 바꿨다"를 말없이 가르친다).

| 난이도 | 적색 차단 구간 | 녹색 차단 구간 | 사람에게 요구되는 것 |
|---|---|---|---|
| low | 파랑 (자유색) | 흰색 (유일색) | 그냥 보인다 |
| **mid (기본)** | 노랑 · 초록 · 청록 · 흰색 | 빨강 · 노랑 · 파랑 · 청록 | 합류쌍 — 밝기 비교 or 견본판 대조 |
| high | 빨강 (죽는 색) | 초록 (죽는 색) | 위치 기억 — 검정 미끼 사이에서 골라야 한다 |

- 구간 1 목표는 6색 중 랜덤(검정 제외 — 검정은 영원히 목표가 아니다).
- 같은 색이 연속 두 구간의 목표로 나오지 않는다.
- 난이도는 관리 AI의 강도 파라미터다(PLANNING §4.1 "선택 + 강도 조절") — 기본 mid,
  후반 압박에 high.

## 5. 사람이 푸는 세 갈래 — 설계 보증

셋 다 **법칙을 이해한 사람이 이기는 길**이고, 셋 중 하나라도 지우면 게임이 벌칙이 된다:

| # | 길 | 지탱하는 설계 |
|---|---|---|
| ① | **기억** — 기준광에서 봐둔 위치 | 구간 1이 기준광이다 + 리스폰은 죽은 자리 ±1.5m(§6) — 위치 기억이 근사적으로 유효 |
| ② | **밝기** — 합류쌍의 톤 차이 | 12~15% 갭 규칙(§2) |
| ③ | **견본판** — 기준물 대조 | 맵의 색 견본판(§6): "지금 조명에서 노랑은 이렇게 보인다" |

## 6. 공간 · 구슬 · 견본판

- 공간: trial 공간 재활용 — 같은 맵, 상수만 교체 (PLANNING §7)
- 구슬: **7색 × 10개 = 70개**, 격자 + 지터 배치. 로우폴리 구체 · 플랫 셰이딩 ·
  **자체발광 없음**(조명을 받아야 법칙이 산다)
- 주우면 사라지고 **2초 뒤 같은 색이 그 자리 ±1.5m에 리스폰** — 색 분포 유지 + 기억(§5-①) 유효
- **견본판**: 맵 가장자리 1~2곳. 7색 라벨("빨강"·"노랑"…) 밑에 현재 조명 적용색 견본.
- 다른 참가자의 아바타 · 줍는 모션은 보인다. 남을 따라 줍는 것도 전략이다 — 그것도 토론
  재료가 된다("쟤만 따라 주웠는데 쟤가 다 맞더라").
- **정오는 아무에게도 실시간으로 보이지 않는다 — 본인에게도.** 이유 셋: ⑴ 본인 피드백을
  주면 두어 개 주워보고 조명을 역산할 수 있어 퍼즐이 깨진다 ⑵ 첫 실수자가 그 자리에서
  낙인찍힌다 ⑶ 전원이 모달에서 처음 알아야 §3 모달의 임팩트가 산다.

## 7. 조작과 판정

- WASD 이동, E 줍기
- E → 클라가 `game_pick { ballId }` 송신 (`runtime.ts`의 스텁 자리)
- 서버 판정: 거리 ≤ 1.2m · 쿨다운 0.8초 · 구슬 존재 → 정오 = `ball.trueColor ===` 그 시각의 목표색
- 클라는 구슬의 `trueColor`를 **절대 받지 않는다** — `{id, pos, 표시색}`뿐. 전환 때 서버가
  전 구슬의 새 표시색 + 조명 tint를 일괄 브로드캐스트한다. 콘솔을 파도 화면에 보이는 것
  이상이 나오지 않는다(P8).

## 8. 기록 — 무엇이 판별 재료가 되나

| 필드 | 내용 | 원칙 |
|---|---|---|
| 정답률 (구간별) | 맞은 줍기 / 전체 줍기 | P2 — 무리 평균 대비 편차로만 노출 |
| **전환 후 첫 줍기까지** | 전환 시각 → 다음 줍기 시도까지 초 | **P3 — 메인 판별 수치.** 사람은 멈칫한다(평균 5초대) — 기계는 안 멈칫한다 |
| 전환 창 정오 | [전환, +3초] 안의 시도 수 · 정오 | P3 |
| **오답의 방향** | 오답 중 **합류색 오답 비율** — 노랑을 초록으로 착각(물리적으로 정직한 실수) vs 무관한 색을 주움(막 찍음) | P4 — 사람의 오답은 합류색에 몰린다. 오답 **수**가 사람 같아도 **방향**이 다르면 티가 난다 |
| 미끼 | 검정 미끼를 주운 횟수 (high 구간) | 사람은 밟는다 — 한 번도 안 밟는 좌석이 티 난다 |
| 헤맨 시간 · 견본판 체류 | 줍지 않고 이동만 한 시간 · 견본판 3m 이내 체류 시간 | "확인하러 갔다 왔다"는 변호 재료 — 주장 판정(§4.2)이 대조할 원자료 |

결과 모달 예시 (PLANNING §3 형식):

```
색 사냥 — 적색 차단 직후 (20~23초)
첫 줍기까지          무리 평균 5.2초
SUBJECT 01   5.8초
SUBJECT 04   0.9초   ← 편차
합류색 오답 비율      무리 평균 81%
SUBJECT 04   17%    ← 오답의 방향이 다르다
```

## 9. AI 좌석 — 서버 프로파일 (P9)

`fall/npc.ts`와 같은 자리. LLM은 테스트 시작 전 `precision` 하나만 정하고(`aiStrategy`)
실행은 서버가 한다.

인간 분포 (좌석마다 샘플):

| 파라미터 | 평균 | σ |
|---|---|---|
| 줍기 간격 | 3.5초 | 1.0 |
| 기준 구간 정답률 | 0.92 | 0.05 |
| 전환 후 첫 줍기까지 | 5.5초 | 2.0 |
| 합류 구간 정답률 | 0.65 | 0.15 — 오답의 85%는 합류색으로 |
| high 구간 정답률 | 0.55 | 기억 모델: 구간 1에서 지나친 구슬만 안다 |
| 전환 후 견본판 확인 확률 | 0.6 | 실제로 걸어갔다 온다 |

**`precision`은 시간축에만 물린다:**

- 전환 후 첫 줍기까지: `lerp(인간 샘플, 0.4초, precision)`
- 견본판 확인 확률: `lerp(0.6, 0, precision)`
- 미끼 밟기: `lerp(인간 샘플, 0, precision)`

**정답률에는 물리지 않는다** — 항상 인간 분포 안(무리 평균 ±1.5σ)에 클램프한다. 정확도에
물리면 편차가 폭발해 P2가 무의미해진다. AI는 "사람만큼 틀리되, 멈칫하지 않는" 좌석이다 —
티는 오직 시간축에서만 난다. 오답을 낼 때의 방향도 인간을 따른다(85%는 합류색으로).

## 10. 연출

- 전환: 0.5초 조명 램프 + 지지직 SFX + 관리 AI 방송 한 줄("스펙트럼 조정." — `pa` 음색)
- **시연 컷: 적색 차단이 내려앉는 순간** — 화면이 청록빛에 잠기고 빨간 구슬 열 개가 일제히
  검게 죽는다. 심사에 남는 한 장면(PLANNING §7 "랜드마크 하나만 제대로"와 같은 원리)
