1. LLM 공급자와 런타임

게임에서 LLM 은 네 곳에 쓰인다. 뒤의 둘은 관리 AI(참가자가 아닌 심판 역할)의 자리다.

  • 대사 생성 — AI 참가자와 사람 대역이 대화 중 하는 말. 둘은 같은 함수를 지난다
  • 전략 결정 — AI 참가자만 한다. 물리 게임을 시작하기 전에 이번 판에서 얼마나 정확하게 움직일지를 스스로 정한다
  • 대화 분석 — 오간 대화를 읽고, 누가 사람답지 않게 말하는지를 따져 각자의 의심도를 올리거나 내린다
  • 답변 판정 — 답변 강제권이 걸린 질문에 한 답이 기록·앞말과 어긋나는지, 답을 피한 것인지 본다

호출 경로는 실행 환경에 따라 달라진다.

실행 환경적용 위치연결 방식
배포본Cloudflare WorkerOpenAI API 키 하나로 동작한다
로컬 개발개발 서버API 키 없이 Claude Agent SDK 로 Claude 구독을 통해 동작한다. 워커에서는 프로세스를 띄울 수 없어 배포본에는 쓰지 못한다

모델 등급 매핑

모델은 두 등급으로 나눠 쓴다. 먼저 역할이 요구하는 추론 수준으로 등급을 정하고, 같은 등급 안에서 호출 횟수와 단가를 보고 배포 모델을 골랐다.

  • 관리 AI 가 하는 일(대화 분석 · 답변 판정)은 지금 한 말과 앞서 한 말을 대조해 모순을 찾고, 참가자의 말을 공개된 기록과 맞춰 보는 것이다. 실제 추론이 필요해서 상위 등급을 쓴다.
  • 참가자가 하는 일(대사 생성 · 전략 결정)은 정해진 성격으로 짧은 한 마디를 만들거나 숫자 하나를 정하는 것이다. 상위 추론이 필요하지 않아 한 등급 아래로 충분하다.

등급을 정한 뒤에는 벤치마크로 클로드 모델과 동급인 OpenAI 모델을 짝지었다.

2. AI 동작 설계

말

관리 AI 는 참가자들이 주고받은 대화를 일정 간격으로 읽고, 말한 사람마다 의심도를 조정한다. 이때 누가 AI 인지는 알지 못한다. 판단 근거는 방금 오간 대화와 공개된 물리 게임 기록뿐이다.

말을 읽을 때 보는 기준은 다음 두 가지다.

판단 기준의심도 상승 (+)의심도 하락 (−)
① 말하는 방식사람이 안 쓰는 정밀함(수치·단위를 굳이 정확히), 감정이 빠진 설명체, 질문을 받은 뒤에야 도는 대답, 자기 기록만 매끄러운 해명, 남의 말을 정리하는 사회자 말투, 같은 문장 구조의 되풀이즉흥적인 농담·욕설·오타·말끊김, 감정이 앞선 반박, 흐릿한 기억을 흐릿하게 말하기, 불리한 것을 그냥 인정
② 앞뒤가 맞는가같은 사람이 앞서 한 말과 지금 한 말이 어긋나는 경우스스로 앞서 한 말을 정정하는 경우

행동

의심도는 말로만 오르지 않는다. 방 안에서 몸이 어떻게 움직이는지도 본다. 이쪽은 LLM 을 부르지 않고 규칙으로 센다.

행동세는 기준의심도
굳음한자리(반경 0.4m)에서 25초 넘게 움직이지 않는다+5
뒷걸음보는 쪽과 어긋난 방향으로 1.2m 넘게 물러선다+5

같은 사람이 같은 행동에 거듭 걸리면 한 번에 5씩 더 문다. 대신 몸으로 오를 수 있는 값은 한 사람당 30에서 멈춘다 — 격리선이 100 이라 몸만으로는 격리되지 않는다. 자판에서 잠깐 손을 뗐다고 폐기되면 게임이 아니기 때문이다.

성격 설정

AI 참가자는 아홉 가지 성격 중 하나를 받아 그 말투로만 말한다. 한 마디는 25자 안팎이고(서버가 80자에서 자른다), 사람과 같은 간격(3.5~10초)으로 나가며, 지목과 철회도 사람과 같은 경로를 지난다. 그래서 통신 내용만으로는 사람과 구분되지 않는다. 사람 대역도 같은 성격 풀에서 뽑고, 아홉 모두 같은 등급(gpt-5.6-terra)을 쓴다.

성격말투 특징
따지는 사람말이 어긋나면 바로 짚는다. 반말.
기억력 좋은 사람순서와 시간을 정확히 짚는다. 존댓말.
말수 적은 사람짧게 답하고 잘 나서지 않는다. 반말.
분위기 맞추는 사람남 말에 잘 얹는다. 반말.
재는 사람단정 안 하고 길게 본다. 존댓말.
과장하는 사람뭐든 세게 말한다. 반말.
곁길로 새는 사람엉뚱한 디테일을 묻는다. 존댓말.
직감으로 찍는 사람근거 없이 당당하다. 반말.
옛날 얘기로 받는 사람뭐든 경험에 빗댄다. 존댓말.

AI 참가자에게는 조건이 하나 더 붙는다. 세 게임이 열리기 전에 각각 얼마나 정확하게 움직일지를 스스로 정하는데, 너무 정확하면 기록이 그대로 의심의 근거가 되고 너무 부정확하면 순위에서 밀린다. 그 선택이 기록에 남아 이어지는 대화의 단서가 된다.

3. 제작 파이프라인

3D 공간과 소품, 캐릭터 애니메이션, 인트로 영상은 모두 생성형 도구로 만들었다. 사람이 판단한 것은 무엇을 만들지와 어디에 배치할지뿐이다. 다만 생성 결과물을 그대로 쓴 경우는 없다. 원본은 모델 하나가 수십 MB 라, 브라우저에서 돌아가는 크기(수백 KB~수 MB)로 줄이는 후처리를 반드시 거친다.

4. Claude Code — 개발 도구

구현과 문서화, 반복 개선에 Claude Code 를 썼다. 테스트를 돌리고 실패와 측정값을 읽어 고친 뒤 다시 돌리는 과정을 루프로 자동화해, 실행과 진단과 수정이 한 명령으로 이어지게 했다.

병합 커밋을 제외한 205건 중 202건(99%)이 Claude 와의 공동 작성이며, 커밋 메시지에 모델별 기여가 기록돼 있다.
